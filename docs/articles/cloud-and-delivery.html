NOTE 07 / Cloud & delivery

Ship less privilege.

2 MIN READEDITED 30 OCT 2026

Infrastructure is easier to reason about when identity, permissions, and changes have explicit boundaries. Start with the smallest delivery system you can explain.

Prefer short-lived identity

AWS recommends federation and temporary credentials for people, IAM roles for workloads, MFA, and least privilege. Review unused permissions and credentials rather than allowing an initial setup to become permanent policy. [1]

When a GitHub workflow needs AWS access, OIDC can replace stored long-lived AWS credentials. Restrict the role’s trust to the intended repository and branch or environment, and restrict what the resulting session can do. Federation changes how identity is obtained; it does not remove the need for a narrow permissions policy. [2]

Use a small publishing pipeline

This repository does not need AWS access. Its GitHub Pages workflow checks the content, builds static files, uploads the publication artifact, and deploys it. The build job has read access to source. The deployment job receives Pages write and identity-token permissions. Pull requests run validation without a deployment job. [3]

Treat publication as a data boundary

A static site delivers its files to visitors. Put public content in the artifact, and keep operational credentials out of source, examples, logs, and generated files. The build uses a curated source map; it never connects to Notion or performs a raw notebook export.

The included secret-pattern check is a guardrail for recognizable formats, not proof that a file contains no secret. Review the staged changes before pushing. If a real credential is exposed, revoke or rotate it and investigate its use; deleting the line does not invalidate the credential.

Practice: explain every permission

Read .github/workflows/pages.yml. For each permission, identify which job needs it and why. Then inspect the uploaded directory and verify that it contains only the site and intended downloads. Use the publishing guide to configure Pages after creating the remote repository.
