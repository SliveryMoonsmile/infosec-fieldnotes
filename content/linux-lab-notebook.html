A reproducible lab starts with a question and ends with a record someone else can inspect. Terminal organization helps preserve that chain.

Use a small evidence folder

The UNIX/Linux entries mention Git and builds; the tmux entry already contains a practical command reference. Combine those ideas into a working convention: one folder for the experiment, one note for context, and one place for results. Record the system, tool version, exact input, and expected outcome before interpreting output.

mkdir -p lab-notebook/results
cd lab-notebook
date -u +%FT%TZ
uname -sr
tmux -V
ip neigh show > results/neighbors.txt

The neighbor command is read-only and specific to Linux. Its output describes the local machine’s neighbor table, not an inventory of the whole network. Review addresses and identifiers before sharing it. [2]

Keep a session, separate the tasks

tmux groups terminal programs into sessions, windows, and panes. Detach to leave the session running and attach later. This can preserve work through a client connection drop; it does not keep a process alive through a server shutdown. [1]

tmux new -s security-lab
# Inside tmux: Ctrl-b, then c creates a window.
# Ctrl-b, then % splits into left and right panes.
# Ctrl-b, then double quote splits into top and bottom panes.
# Ctrl-b, then d detaches.
tmux ls
tmux attach -t security-lab

In the default key bindings, press the prefix Ctrl + b, release it, then press the command key. Keep a notes window and a command window so the result and its explanation do not get mixed together.

Write down what would change your mind

A short record can be enough: question, environment, command, observation, interpretation, and limitation. Separate an absent observation from proof of absence. For example, an empty neighbor table says little about devices on another link.

Practice: rebuild the result

Run the local SQLite lab from the downloads page. Close the terminal, open a fresh one, and run it again using only the recorded instructions. If you must remember an undocumented dependency or setup step, add it to the record. The exercise succeeds when the result is reproducible, not when the terminal looks busy.
